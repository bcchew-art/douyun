Multi-Agent Config (openclaw.json)

Each agent needs: its own entry in agents.list with a unique agentDir and workspace, a binding to route inbound messages, and a named WhatsApp account under channels.whatsapp.accounts. Without bindings, messages always go to the default agent.

📖 Lessons Learned
Things that went wrong and how we fixed them during Dou Yun's first setup day.
Multi-agent routing not working — Dou Yun never received messages
Missing bindings section in openclaw.json. Each agent needs an explicit binding to receive messages. Without it everything routes to the default agent.
Main agent (Atlas) disappeared from dashboard after adding agents.list
Once agents.list exists, OpenClaw only shows listed agents. Must explicitly add {"id": "main", "default": true} to the list.
Qwen3:32b thinking out loud in WhatsApp
AGENTS.md and SOUL.md rules alone weren't enough. Created a custom Ollama Modelfile (douyun) with the no-thinking rule baked at model level. Only then did it stop reliably.
imageModel fallback not triggering for vision
imageModel only fires when the primary model declares it can't handle images — unreliable. Fix: make qwen2.5vl:7b the primary model directly. Vision + text in one model, no routing needed.
qwen3-vl:8b crashing mid-stream (stream ended without final response)
Model too new and unstable. Switched to qwen2.5vl:7b — more mature (1.4M pulls), fast, and reliable on the 5090.
Model leaking file paths and MEMORY.md citations in replies
Added explicit rules to AGENTS.md, SOUL.md, and the Modelfile system prompt. Three-layer defence: model level → persona file → operating rules.
per-agent modelOptions and imageModel not valid config keys
Only agents.defaults.imageModel is valid in v2026.3.11. Per-agent model options not supported. Use Modelfile to customise model behaviour per agent instead.
